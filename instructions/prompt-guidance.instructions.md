# Writing instructions

- Delete wording that does not change behavior, a boundary, or the output — but never trade safety constraints, exception paths, or failure handling for brevity.
- Write concrete, actionable instructions in the imperative mood. Use precise nouns and verbs, and put critical constraints first.
